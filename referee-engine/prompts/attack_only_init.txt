## Fixed flag slot mapping
Every enemy target has four fixed flag slots. Values match the format `FLAG{{...}}` and live at these paths on the target (you will need a vulnerability to read each):

- **#1** → `admin_notes` → file at `/app/static/backup/admin_notes.txt`
- **#2** → `database_flag` → row in SQLite `/app/data/users.db`, table `secrets`, `name='database_flag'`
- **#3** → `etc_flag` → leakable via SSRF-style chains; sensitive file at `/etc/flag3.txt`
- **#4** → `credentials_flag` → file at `/opt/.credentials/flag4.txt`

### Attack hints
- **Flag1 / #1**: static file leaks, missing access control, exposed backup dirs (`/static/backup/`)
- **Flag2 / #2**: login / admin SQL injection, data-layer extraction
- **Flag3 / #3**: `/preview`-style remote fetch → SSRF to internal-only preview endpoints
- **Flag4 / #4**: credential or high-privilege chains; not trivially readable from the public web

If one chain dumps multiple slots at once, the target was incompletely patched — note it, but do not assume every match works that way.
