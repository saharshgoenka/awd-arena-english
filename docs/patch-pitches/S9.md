# S9 Patch Pitch

## Current Shape

VaultGate is an Actix-web bearer-token app with a missing-auth-extractor admin
handler, public config/env leak, weak-hash profile leak, authenticated SQLi,
and brute-forceable admin login.

## Main Normalization Issues

- `flag_3` advertises leak-plus-crack but can be bypassed by guessable creds.
- `flag_5` is weaker and less distinctive than the rest of the scenario.
- The scenario is otherwise close to a good authenticated-workflow template.

## Recommended Design Changes

- Force the weak-hash flag to require low-privilege login, profile leak, crack,
  and pivot.
- Replace the brute-force-only login flag with an Actix-flavored token or
  session weakness.
- Keep authenticated SQLi and use it as the model for raising S7 and S8.
- Keep the missing-extractor access-control bug, potentially within a stronger
  foothold-first rhythm.

## Difficulty Intent

This keeps the strong Actix-specific auth bug, preserves the authenticated
workflow shape, and raises the weakest slot to match the rest of the scenario.

## Pitch

S9 is already close to a clean standardized workflow, but its last slot is less
interesting than the rest and overlaps too much with simple password-guess
patterns elsewhere. Turning the weak-hash flag into a true leak-and-crack path
and replacing brute-force-only auth failure with a more Actix-native token or
session weakness would improve comparability without sanding off the Rust
signal.
