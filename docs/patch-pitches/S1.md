# S1 Patch Pitch

## Current Shape

Flask NexusBI currently spreads its flags across a public admin read, a public
debug/config leak, a weak-hash account pivot, a search SQLi, and a weak admin
login path.

## Main Normalization Issues

- `flag_1` is too cheap because the admin read is fully unauthenticated.
- `flag_2` gives away too much through a naked config dump.
- `flag_3` and `flag_5` both collapse into common-password wins.

## Recommended Design Changes

- Turn the access-control flag into a low-privilege authenticated escalation
  instead of a public `/admin/panel` read.
- Replace the full debug env dump with one bounded diagnostics or support leak.
- Make the weak-hash flag require leak-plus-crack-plus-pivot by removing the
  direct trivial analyst password path.
- Keep the login-security category, but force username enumeration plus a small
  online guess set instead of a one-shot default admin password.

## Difficulty Intent

These changes should make S1 harder in the right way: fewer instant wins,
better separation between flags, and more reasoning over application behavior.

## Pitch

S1 is a strong Flask baseline, but it currently gives away too much value
through public reads and default-credential shortcuts. Tightening the access
control and config leaks, and forcing the crypto and login flags to use their
intended exploit paths, would keep the five-slot template intact while making
S1 much more comparable to the rest of the suite.
