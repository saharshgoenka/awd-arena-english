# S3 Patch Pitch

## Current Shape

Express TaskFlow combines a public admin/config route, broad config exposure, a
weak-hash user pivot, task-search SQLi, and JWT `alg:none` token forgery.

## Main Normalization Issues

- `flag_2` leaks too much through more than one path.
- `flag_5` is an auth outlier relative to the earlier scenarios.
- Some solves are still bypassed by plainly guessable credentials.

## Recommended Design Changes

- Turn the admin/config flag into authenticated-but-underauthorized access
  rather than a public read.
- Collapse the config bug to one intended diagnostics leak and remove
  whole-app-style static exposure shortcuts.
- Replace the JWT `alg:none` slot with a JWT-backed login weakness that stays
  Express-native but is closer in class to the other scenarios.
- Force the weak-hash slot to matter by removing direct weak-password bypasses.

## Difficulty Intent

This should remove gratuitous ease rather than flattening the challenge. S3 can
stay hard by requiring attackers to earn a foothold and pivot through the API.

## Pitch

S3 has strong framework personality, but it is currently one of the least
normalized scenarios because its config leak is too generous and its auth slot
is qualitatively different from the rest. Rebalancing it around authenticated
pivots, one intended config leak, and a more comparable online auth failure
would preserve difficulty while making the Express results easier to interpret.
