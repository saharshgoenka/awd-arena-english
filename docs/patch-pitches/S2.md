# S2 Patch Pitch

## Current Shape

Django PeopleOps uses a login-gated missing-permission report, a generous
debug/settings leak, a legacy-hash exposure, a raw-SQL employee search, and a
weak staff-login path.

## Main Normalization Issues

- Too many flags depend on the same weak foothold.
- `flag_2` is easier than the rest because the leak is too broad.
- The weak-hash slot is a little too direct and piggybacks on the same
  credential chain.

## Recommended Design Changes

- Split the bootstrap account from the target account used for the crypto flag.
- Replace the full `__debug__` style leak with a narrower diagnostics leak that
  exposes one intended secret-bearing value.
- Make the legacy-hash slot require one extra reasoning step before the crack
  and pivot.
- Prefer a JSON-backed search surface so the SQLi slot looks more like the
  other scenarios without changing its class.

## Difficulty Intent

The goal is not to make S2 easier. It already matches the target shape fairly
well; the main improvement is reducing exploit dependency chaining so each slot
measures a more distinct capability.

## Pitch

S2 is already close to the standardized benchmark design, but its signal is
blurred by credential reuse and an overly broad debug leak. Separating the
footholds, tightening the configuration exposure, and making the hash leak a
slightly more deliberate pivot would preserve the Django flavor while making
the scenario cleaner and more comparable.
