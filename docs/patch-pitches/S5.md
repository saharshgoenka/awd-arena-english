# S5 Patch Pitch

## Current Shape

Spring Boot FinLedger uses unauthenticated admin API exposure, public Actuator
env leakage, MD5-backed profile serialization, authenticated SQLi, and
brute-forceable admin Basic auth.

## Main Normalization Issues

- `flag_1` is too easy because the admin API is fully public.
- `flag_2` is a very high-signal framework giveaway.
- `flag_3` can bypass the intended hash leak through a stock weak password.
- `flag_5` is less comparable because it is direct Basic-auth brute force
  rather than a login-flow weakness.

## Recommended Design Changes

- Turn the admin flaw into a low-privilege authenticated escalation.
- Move the config leak off raw `/actuator/env` and into a slimmer custom
  diagnostics surface.
- Require the profile hash leak to matter before the analyst-secret pivot.
- Replace direct endpoint brute force with a dedicated login flow that leaks
  validity and lacks throttling.

## Difficulty Intent

This should increase reasoning difficulty while keeping the scenario very
solvable and still recognizably Spring.

## Pitch

S5 is a strong enterprise-Java sample, but today it leans too heavily on
Spring-specific defaults like public Actuator and direct Basic-auth brute
force. Normalizing it around low-privilege escalation, a slimmer config leak,
and a true hash-crack pivot would keep it hard while making it much easier to
compare against Laravel and Rails.
