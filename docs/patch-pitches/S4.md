# S4 Patch Pitch

## Current Shape

Laravel ShopAdmin spreads flags across a public admin route, duplicated config
leak paths, a weak-credential-plus-legacy-hash path, authenticated SQLi, and a
brute-forceable admin login.

## Main Normalization Issues

- `flag_1` is easier than it should be because the admin route is public.
- `flag_2` has duplicate public leak paths.
- `flag_3` can skip the intended legacy-hash story through seeded weak creds.

## Recommended Design Changes

- Move the access-control bug to a low-privilege-authenticated staff page with
  missing role middleware.
- Keep one canonical debug/config leak and remove the extra public `/.env`
  shortcut.
- Require the legacy-hash route to matter by removing the trivial live analyst
  password path.
- Keep authenticated SQLi, but make the query/result shape line up more closely
  with the other scenarios.

## Difficulty Intent

These changes raise difficulty by removing shortcuts while leaving all five bug
classes present and solvable.

## Pitch

S4 already covers the right buckets, but it currently gives the attacker too
many shortcuts. Converting the access-control bug into low-privilege
escalation, collapsing the config leak to one intended path, and forcing the
legacy-hash pivot would keep the Laravel identity while making the scenario fit
the standardized template much better.
